# Implementation Progress

This record captures the implementation passes against the integration plans. It is intentionally separate from the tracker checkboxes: a checkbox is only closed after its phase gate and release evidence are complete.

## Implemented in this pass

### WPrint core

- SDK 1 revision 5 is now the current compatibility pair while revisions 0–4 remain accepted.
- SDK reference/changelog and the new-plugin development example now consistently advertise revision 5; the migration notes retain revisions 0–4 as supported legacy contracts.
- Managed bridge manifests can declare authentication mode, proxy allowlists, private `/data` storage, resource limits, read-only root filesystems, dropped capabilities, and no-new-privileges.
- Managed containers receive deterministic spec fingerprints. A first activation creates the canonical container; updates use the candidate/promote path described below.
- Revision-5 manifests can no longer choose a Docker network; the host resolves the configured/current plugin network and excludes the untrusted network field from runtime fingerprints.
- Legacy SDK revisions retain their declared-network compatibility path, while revision 5 rejects network selection at manifest validation and runtime activation; focused validator/dependency tests cover both behaviors.
- Revision-5 managed image references are now required to end in a canonical `@sha256:<64-hex>` digest. The scaffold generator emits an explicit digest-shaped placeholder instead of `:latest`, while SDK revisions 0–4 remain accepted.
- Managed service declarations now carry and enforce `stopGracePeriodSecs` and numeric `security.user`; Docker activation applies `--stop-timeout`/`--user`, and one-shot image healthchecks run with an explicit `--entrypoint`, `--network none`, read-only root, and bounded tmpfs so image entrypoints cannot hijack the check.
- Managed service declarations also support a host-bounded `/tmp` tmpfs size; Cura declares 1024 MB and the runner retains a 256 MB fallback for older read-only manifests.
- Focused dependency/manifest coverage now passes 31 tests / 96 assertions, including invalid user, stop-grace, and tmpfs rejection plus the explicit healthcheck command shape.
- Managed runtime updates now start a digest/config-mismatched candidate on an isolated network alias, run the authenticated bridge healthcheck against that candidate, attach the live alias, stop the old container, and promote the candidate. Failed candidates are discarded while the old canonical container remains available.
- Container operations now cross a typed/testable `PluginContainerClient`; image pulls and healthchecks use explicit per-operation timeouts, while digest inspection remains mandatory for revision-5 immutable references.
- The default dependency-service adapter now forwards those per-operation timeouts into Laravel's process runner instead of silently falling back to the global command timeout; focused tests assert pull and healthcheck deadlines separately.
- Managed-plugin updates now snapshot the previous package/database/runtime state and restore it, including re-enabling the previous bridge, when the new version fails its healthcheck; retained volumes are deliberately untouched.
- Archive installation now stages the extracted package and dependency/image preparation before changing the plugin record, restoring the prior document or deleting a new record and staged files when preparation/save fails. Pulled immutable images remain cached intentionally; they are content-addressed and never become active without a healthy promotion.
- Bridge tokens are generated by WPrint, encrypted in dependency state, injected only during container creation, and used by bridge actions/healthchecks and the proxy.
- `plugin:reconcile-runtime` restores enabled managed services after a host/container restart.
- `plugin:install-builtins` is idempotent and is invoked during non-test server bootstrap for packages present in the production image.
- Rollout controls are now explicit: `WPRINT3D_BUILTIN_CURA_ENABLED` gates the Cura built-in inventory, `WPRINT3D_BUILTIN_CURA_AUTO_ENABLE` controls activation separately, `WPRINT3D_PLUGIN_RUNTIME_PROXY_ENABLED` provides an emergency 503 kill switch without exposing the runtime, and `WPRINT3D_PLUGIN_RUNTIME_RECONCILE_ENABLED` can pause startup reconciliation without disabling unrelated plugins.
- Built-in distribution now has a host-owned inventory at `resources/plugins/builtin/index.json`, checksum/path validation, trusted-package checks, compatibility-record/image matching, version-preserving installation/update behavior, optional-failure isolation, and an atomic `scripts/stage-builtin-plugin.sh` release step. The WPrint image workflow accepts explicit immutable signed Cura and compatibility assets and stages them before the production image build; no production `.w3dp` binary is committed to source.
- Built-in staging now prepares and hashes the archive part, validates manifest/signature/compatibility before commit, atomically promotes the archive and inventory parts, and restores prior files if either promotion fails. A disposable-container run passed both the successful stage and invalid-compatibility rollback paths.
- Built-in compatibility records are now validated as complete release identities at both staging and host installation: schema, plugin/SDK identity, archive checksum and filename, minimum WPrint core version, canonical digest-pinned image, and both required platforms must agree with the signed manifest.
- The WPrint production-image workflow now has an explicit release-only `workflow_dispatch` that downloads the exact Cura archive and compatibility record over HTTPS, verifies both hashes and the configured signer key, stages and verifies the built-in inventory, and carries that artifact into every architecture build. Ordinary pushes and pull requests keep the inventory empty by design.
- The built-in preparation job uploads the verified `resources/plugins/builtin` tree as an artifact and architecture builds download it before Bake, so the staged package is not lost across isolated runners.
- Runtime updates stop managed containers before replacing the package and re-enable the healthy version when appropriate.
- Runtime proxy and server-to-server G-code import endpoints are available under authenticated, rate-limited same-origin routes.
- Browser-facing plugin management responses now redact managed runtime URLs, bearer-token ciphertext, container/network identifiers, host paths, and dependency state while preserving the complete state for internal lifecycle calls.
- Administrator plugin diagnostics now report desired image, resolved image IDs/digests, container running/health/spec-match state, retained volume presence, lifecycle timestamps, and bounded latest lifecycle log metadata without exposing Docker mounts, environment, or credentials.
- Retained heavyweight-plugin storage now has an administrator-only HTTP deletion flow. The host derives deterministic managed volume identities, requires the selected identity in the request, refuses enabled plugins and foreign volumes, and exposes the destructive confirmation in the WPrint plugin settings UI with localized copy.
- Added the operational [`plugin-runtime-backup-and-recovery.md`](../../plugin-runtime-backup-and-recovery.md) runbook, documenting the backup boundary, sanitized support diagnostics, safe volume snapshot/restore sequence, schema-corruption handling, rollback preservation, and explicit data-loss deletion policy.
- The administrator log bundle now accepts explicit `includePlugins` consent and adds only `wprint3d/plugin-support.json`: bounded sanitized manifests, lifecycle logs, built-in inventory, runtime diagnostics, and (when the enabled gateway is reachable) its authenticated build/readiness snapshot without meshes, G-code, credentials, or host paths.
- Proxy path matching is segment-boundary aware (so `/api/v1evil` cannot match `/api/v1`), rejects traversal/NUL paths, and artifact imports use bounded temporary writes followed by an atomic move.

### Cura Web UI sidecar

- The gateway has a SQLite-backed store for jobs and artifacts, WAL mode, upload records, and startup recovery of interrupted jobs.
- Job progress/stage and the bounded event history are now persisted in SQLite, restored on startup, and wired through the event bus so polling/reconnect clients do not lose the durable terminal/progress record.
- SQLite artifact payloads now use a private per-database filesystem tree with atomic `.part` replacement and metadata (storage key, byte size, SHA-256); legacy JSON artifacts remain readable for migration compatibility.
- Production `.sqlite` deployments use the SQLiteStore overrides for job state, idempotency, events, uploads, and file-backed artifacts; the JSON/MemoryStore path remains an explicit development/test adapter rather than a production job source of truth.
- A FastAPI lifespan worker owns queued jobs in production; the legacy background-task fallback remains only when lifespan is not active so existing tests/development clients remain deterministic.
- CuraEngine execution now uses `asyncio.create_subprocess_exec`, concurrent stdout/stderr drains, process-group TERM/KILL cancellation, timeout enforcement, and shutdown cleanup.
- A lifespan cleanup task removes expired unclaimed uploads and terminal artifacts without following unvalidated paths; storage quota exhaustion returns `507 Insufficient Storage`.
- Multipart model uploads return `uploadId` and SHA-256 metadata. CuraEngine accepts either an upload ID or legacy embedded bytes.
- WPrint bridge auth is supported through the injected runtime token and trusted user header.
- Bridge lifecycle health checks now retry transport-level startup failures, and bridge action/health requests include the injected bearer token plus trusted plugin/user identity headers.
- Managed bridge actions, hooks, and healthchecks now share a typed host-owned HTTP client that resolves the persisted runtime URL/token state, supports streamed requests, and rejects unresolved or invalid runtime URLs. Browser callers cannot supply its base URL or bearer token.
- API 1.1, upload contracts, polling event fallback, and embedded runtime context are implemented.
- The sidecar Dockerfile is non-root, disables runtime engine downloads, requires explicit pinned CuraEngine/resource URLs, and exposes `/data` as the durable volume.
- The sidecar entrypoint validates bridge identity, `/data` writability, and the compiled `CuraEngine help` command; `/api/v1/ready` is an authenticated readiness check distinct from the public liveness endpoint.
- CuraEngine 5.12.1 and Cura resources are source-built from the pinned lock commits/checksums. A small reproducible patch file fixes three upstream compile issues without changing the selected feature set, and Conan shared libraries are copied into the runtime image so the non-root binary is self-contained.

- The Node and Python base image indexes are pinned by digest in the Dockerfile and recorded in the same lock, so rebuilding the release cannot silently move to a newer base tag.
- The local native-amd64 engine stage rebuilt successfully with the newly pinned Conan archive (CuraEngine compilation completed in about 285 seconds). A full runtime image rebuilt with the lock, emitted `conanConfigCommit` in `build.json`, passed CuraEngine help, authenticated readiness, and the non-root/read-only security audit. The existing native image/real-cube fixture passed twice, including cancellation and restart on the same named volume. The Dockerfile static check and lock verifier also pass.

The local host can execute arm64 containers through QEMU, but the full source compile was intentionally stopped after reaching CuraEngine compilation because it is not a meaningful substitute for a native arm64 runner.

It accepts a checksum-pinned unsigned Cura source tarball, rejects traversal/link/oversize members before extraction, signs only in the `wprint-release-signing` environment, verifies the resulting package as trusted, and publishes no private key material. Cura's `stage-w3dp` job emits the deterministic tarball plus checksum needed by that handoff.
- The WPrint production workflow authenticates Docker Hub in both the per-architecture push jobs and the manifest aggregation job; a static release guard now prevents anonymous-pull regressions that can turn a valid multi-architecture build into a registry-rate-limit failure.
